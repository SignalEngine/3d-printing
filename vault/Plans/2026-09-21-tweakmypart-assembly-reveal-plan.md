## 1. The sandbox says where the parts go — `worker/job/system_prompt.md`, `worker/job/run_job.py`
- New deliverable next to `parts.json`: `/job/out/assembly.json` = `{ "units": "mm", "parts": [{ "name": "wall-clip", "instances": [{ "position": [x,y,z], "rotation_deg": [rx,ry,rz] }, …] }], "context": { "note": "<one line: what the parts attach to>" } }`. One instance per printed copy (`count` copies → that many instances), positions in one shared frame where the assembly sits as it will be used (e.g. the two clips 154.44 mm apart, the rod between them). Rule in the prompt: "Write assembly.json as soon as parts.json is complete; if the parts are used separately (no assembly), still write it with every part laid side by side." Validate in `run_job.py` (`parse_assembly`: names must exist in parts.json, instance count == count, finite numbers) — an invalid or missing file is not a failure: the host falls back to the plate layout for the assembled view and logs "No assembly layout — showing the parts side by side".
- Two GLBs are built on the HOST (`worker/worker.py`, trimesh, after the gates pass; never inside the sandbox): `assembled.glb` (each part mesh copied per instance and transformed) and `plate.glb` (every copy laid flat on a 256×256 grid with 8 mm gaps, largest first, each on its 3MF print orientation, centred). Both uploaded; `files.assembled`, `files.plate` on the design (`worker:reportResult` validators + `designs.get` → `assembledUrl`, `plateUrl`). `files.glb` stays (the single-part legacy) — `designs.get` returns `assembledUrl ?? glbUrl` so old designs keep working.
- Versions during the build are unchanged (per-part GLB per new 3MF).

## 2. The ready page — `components/design/ReadyPage.tsx`, `components/mascot/TabletPreview.tsx`, `components/ModelViewer.tsx`
- Tablet shows **assembled** by default. A small segmented control under the screen: **Assembled · Print plate** (also in the full-screen viewer). Plate view uses `plateUrl`.
- **The reveal = going together.** Order, with no gap and no early peek: (1) his `done` beat plays with the tablet screen dark (nothing on it, not the last version); (2) the transform-in clip; (3) the parts appear on the plate layout and fly to their assembled positions over 1.4 s (each instance eased, staggered 80 ms, `reduced motion` = instant cut to assembled). To do this the viewer loads `plate.glb` and `assembled.glb` once, matches instances by name+index (both GLBs name their nodes `<part>-<i>`), and tweens transforms; when either file is missing, fall back to today's print-in reveal on the single GLB. `ModelViewer` gets `mode: "assembled" | "plate"` and `assembleKey` to trigger the tween; the existing `revealKey` path stays for versions.
- "It shows the part before the reveal": on ready, the last build version must not be on the screen before step (1) — audit `WorkingPage` → `ReadyPage` handover (`skipEntrance` false on a live transition) and the tablet's screen contents during the done beat; write a test that the screen is empty until the transform-in finished.
- The camera: after the fly-in, one slow 20° orbit (3 s) then rest; no extra zoom step.
