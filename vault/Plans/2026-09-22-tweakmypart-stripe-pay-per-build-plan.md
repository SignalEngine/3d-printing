## Behaviour
1. **Approve when payments are ON** (`PAYMENTS_ENABLED=true`): `approveBrief` no longer queues the build. It records the answers and the chosen approach exactly as today, sets `status: "awaiting_payment"`, and returns `{ next: "pay" }` — unless the **welcome build** applies (the user's first build, `quotedPricePence ≤ 300`, `users.welcomeBuildUsed` not set): then it queues as today, sets `welcomeBuildUsed`, and returns `{ next: "building", welcome: true }`. With payments OFF (personal mode, today's prod) everything behaves exactly as now — tests must prove it.
2. **Checkout**: a Convex action `payments:createCheckout({ designId })` (owner only, design `awaiting_payment`, quote present) creates a Stripe Checkout Session (mode `payment`, GBP, one line item "Build: <design name>" at `quotedPricePence`, `client_reference_id` = design id, metadata designId/userId, `success_url` `${SITE_URL}/design/<id>?paid=1`, `cancel_url` `${SITE_URL}/design/<id>`), idempotency key = `checkout-<designId>-<quote>`, inserts an `orders` row (`kind: "build"` — extend the union; `amountPence`, `paid: false`), returns the URL. The client redirects. Amount always from the server-side quote.
3. **Webhook**: `convex/http.ts` route `POST /stripe/webhook`, verifying the `Stripe-Signature` with `STRIPE_WEBHOOK_SECRET` (use the `stripe` package already in package.json: `stripe.webhooks.constructEventAsync` with the Web Crypto provider in the Convex runtime — confirm it runs there; otherwise implement the documented v1 HMAC check yourself). On `checkout.session.completed` with `payment_status: "paid"`: mark the order paid (idempotent on the session id — a replayed event does nothing), and if the design is still `awaiting_payment`, queue the design job exactly as `approveBrief` does today (share one internal helper; do not duplicate the queue logic). Store `payment_intent` on the order.
4. **Refund on double failure**: when a design job fails and the design already had its free automatic retry (`retries ≥ 1`) — or the retry path is not available — and it has a paid `build` order, a scheduled internal action refunds the full amount (`refunds.create({ payment_intent })`, idempotency key `refund-<orderId>`), marks the order `refundedAt`, and the failed page says "We couldn't make this — you've been refunded". Make the first failure of a paid build trigger the existing free `retry` automatically (worker side unchanged: Convex queues the retry job when the first attempt fails and an order is paid).
5. **UI**: the Approve button shows the price as today; with payments on it reads "Approve and pay £3.60", then redirects to Checkout; on `?paid=1` the page shows "Payment received — starting your build" until the job starts (the webhook may lag a few seconds). `awaiting_payment` designs show a "Pay £3.60 to build" button on the design page and on the My prints card (status pill "Awaiting payment"). Welcome build: the button reads "Build it — your first one is free". `lib/messages.ts` mappings for every new error.
6. **Env** (documented in `README`/`spec`, NOT set by you): `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `SITE_URL`, `PAYMENTS_ENABLED`. Missing keys with payments on → approve refuses with `payments_unavailable` (and the design stays in `brief`), never a crash.
